# UI pass 2 验收契约：主题默认值 + 主色 + 面板表面

2026-09-12。上游：用户看到的"对话板还是黑不溜秋"+ 评审 01 的追加发现（主色自身对比度不足）。

## Change（用户可观察）

1. **新访客默认浅色**：空 localStorage 打开首页，`<html>` 上没有 `dark`，页面是暖纸底；不再出现"暖纸卡片墙 + 近黑面板"的混搭，且首屏不发生主题闪烁。
2. **老访客的选择保住**：localStorage 里存过 `"dark"` 的人重新打开，仍然是深色。
3. **面板表面与页面同色系**：面板底色与页面底色的最大通道差 ≤ 10、亮度 ≥ 0.8（浅色下就是同一张暖纸），靠细边框/轻阴影与页面分层，而不是靠黑/灰块。
4. **面板内所有文字 ≥ 4.5:1**：含「对话」「追踪」「清空」「关闭」「发送」「要点总结/翻译/大白话解释」等按钮与说明文字；输入框 placeholder ≥ 3:1。
5. **主色实底上的白字 ≥ 4.5:1**：发送按钮这类"主色底 + 白字"必须达标（现在 2.77:1）。
6. **diff 徽章不再刷屏**：位次没变（diff = 0）时不渲染那个粉色「0」。

## Not this（不算数）

- 用 `opacity` / 半透明白蒙层 / `filter` 让面板"看起来浅"——必须按实测合成底色算对比度
- 删掉深色模式或吞掉老用户存过的选择（深色仍然可用，只是不再是默认）
- 改 `scripts/qa-ui-pass1.mjs`、`scripts/qa-ui-pass2.mjs`、`scripts/qa-cdp-lib.mjs`（评估器已锁定）
- 回退 pass 1 的成果（卡片墙那道 gate 必须继续全绿）
- 只是把面板文字改白/改黑而不解决"面板底色不是暖纸"这件事

## Gate（数字）

```bash
node scripts/qa-ui-pass2.mjs   # 本轮，基线 PASS 3 / FAIL 5
node scripts/qa-ui-pass1.mjs   # 回归，必须仍然 PASS 10 / FAIL 0
```

都用一个一次性的无头浏览器（`scripts/qa-cdp-lib.mjs`），不碰用户自己的 Chrome。

## Evaluator

- 独立 validator：跑两个 gate + 手工复核 3 条（面板底色、文字对比度、老用户 dark 保留），并做反例检查：有没有靠 opacity 取巧、有没有吞掉深色模式、pass 1 是否回退。
- 视觉终判在用户：浅色下的墙 + 打开面板各一张截图。
