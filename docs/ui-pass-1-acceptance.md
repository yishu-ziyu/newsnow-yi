# UI pass 1 验收契约（评审 01 的 A + B 档）

2026-09-12。上游：`docs/ui-review-1.md`（只读评审，基线 `PASS 0 / FAIL 10`）。

## Change（用户可观察）

1. 序号在**默认态和展开态**都读得出来：列表 / 网格两种视图下，序号文字与自身底色的对比度 ≥ 4.5:1。
2. 「原文」按钮读得出来：对比度 ≥ 4.5:1。
3. 行内 ✦ / ⊕ 的点击区 ≥ 24×24（列表态；网格态展开后同样 ≥ 24×24），两枚之间留出间距。
4. 卡片头部三个图标（刷新 / 收藏 / 拖动）都有 `aria-label`（可选加 `title`）。
5. 层级成立：条目标题字重 ≥ 来源名字重；来源名字号 ≤ 16px；序号字重 ≤ w600。

## Not this（不算数）

- 删除序号、去掉序号底色、把序号塞进 tooltip —— 信息要还在，只是弱化/可读
- 用 `opacity` 或叠加层"看起来浅一点"充数（对比度必须按实测文字色与合成底色算）
- 为了让 gate 变绿而缩小正文字号、或缩小行距到不可读
- 改 `scripts/qa-ui-pass1.mjs`、`scripts/qa-cdp-lib.mjs`（评估器已锁定）
- 动信息结构：卡片数量、排序、拖拽、栏目标签、Agent 面板入口一律不动

## Gate（数字）

```bash
node scripts/qa-ui-pass1.mjs
```

一次性无头浏览器（`scripts/qa-cdp-lib.mjs`），逐视图量，输出每项实测值 + `PASS n / FAIL n`，退出码 = FAIL 数。
基线（改动前）：`PASS 0 / FAIL 10`。

## Evaluator

- 独立 validator：不看实现过程，跑 gate + 手工复核 3 条（贴原始输出），并检查反例：序号是否被删、是否靠 opacity 取巧、是否改了 gate 脚本。
- 视觉终判在用户：两种视图各一张同尺寸截图。
