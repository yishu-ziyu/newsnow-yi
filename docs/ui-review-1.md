# UI 评审 01：新闻墙（只读评审）

2026-09-12。**没改任何代码**，只做测量和判断。

> 修订（同日）：第一版数字是在用户自己的 Chrome 里量的，当时墙处于网格视图，我把网格数据当成了列表。现在全部用 `scripts/qa-ui-pass1.mjs`（一次性无头浏览器，逐视图分别量）重测，下面已换成实测值。基线：`PASS 0 / FAIL 10`。

## 依据

- **ui-skills**（`npx ui-skills get ibelick/baseline-ui`，已装到 `~/.pi/agent/skills/ui-skills/`）里的硬性约束与 `playbook/use-large-touch-targets`
- **Notion 设计库**：《Not all elements are equal 每个元素并非平等》《Emphasize by de-emphasizing 想要突出重点，先弱化次要内容》《Hierarchy is Everything》
- **WCAG**：正文对比度 4.5:1；WCAG 2.5.8 目标尺寸 ≥ 24×24
- 实测工具：CDP 取 computed style + 几何，对比度按 WCAG 相对亮度公式现算

## 环境

`127.0.0.1:5173`，"最热"栏目 **27 张卡**，视口 1440×1250，列表模式为默认。截图 `/tmp/review-list.png`、`/tmp/review-base.png`。

## 结论

1. **有两个硬性可读性缺陷**：序号和「原文」按钮是白字压在"6% 黑"的近白底上（1.03:1 / 1.17:1），基本读不出来。
2. **层级是平的**：来源名、条目标题、序号都用了 700/900 字重 —— 正是笔记里说的"一面贴满东西的墙，让人不知道该看什么"。
3. **一屏只看得见七分之一**（微博 30 条只露 7.5 行），而卡内滚动没有明确入口。
4. **行内两个图标按钮的点击区只有 8×27px**，卡片头部三个图标没有可访问名称。

## 问题清单

### P0-1 序号徽章：白字 + 近白底 → 对比度 1.03:1

- 位置：`src/components/column/morphing-list.tsx:96`（列表）、`:170`（网格）
- 实测（无头浏览器逐视图量，两个渲染器都中）：
  - 列表：28×28px，白字 on `rgb(239,238,235)` → **1.16:1**
  - 网格：32×32px，白字 on `rgb(240,240,239)` → **1.14:1**
  - 展开态（换主色实底）：白字 on `rgb(248,113,113)` → **2.77:1**（主色本身也不够深）
- 根因：基类里写死的 `text-white` 和 `bgSolid` 里的 `text-neutral-600` 同时存在，UnoCSS 生成的规则里 `text-white` 胜出
  （实际 class：`… text-sm font-black text-white bg-neutral-900/[0.06] text-neutral-600`）
- 为什么算问题：榜单唯一的"排名"信号读不出来；而按照《Not all elements are equal》，序号本来就该是**弱化**的一层，不是靠"看不见"来弱化

### P0-2 「原文」按钮：同样白字压近白底 → 1.17:1

- 位置：`src/components/column/morphing-list.tsx:57`（`${bgSolid} text-white`）
- 实测：`color: rgb(255,255,255)`，`background: rgba(23,23,23,0.06)`，合成底色 `rgb(241,240,240)`，**对比度 1.14:1**
- 为什么算问题：展开条目后最主要的动作按钮看不见

### P1-1 行内 ✦ / ⊕ 的点击区只有 8×27px

- 位置：`morphing-list.tsx:278`（`i-ph:sparkle-duotone px-1 text-sm`）、`:299`（`i-ph:plus-circle … px-1 text-sm`）
- 实测：**17×17px**（网格视图下这两个按钮只在展开时才出现，量的是展开态）
- 依据：ui-skills playbook《Use large touch targets》给 44px；WCAG 2.5.8 最低 24×24
- 为什么算问题：点歪就是"加入对比"——一个会改变状态的破坏性操作

### P1-2 卡片头部三个图标没有可访问名称

- 位置：`src/components/column/card.tsx:201`（刷新）、`:206`（收藏）、`:213`（拖动）
- 实测：三个按钮 `aria-label = null`、`title = null`，尺寸 22×22px
- 依据：baseline-ui 约束「MUST add an `aria-label` to icon-only buttons」
- 为什么算问题：读屏读不出功能；鼠标悬停也没有提示

### P2-1 层级全平（字重全用满）

| 元素 | 实测 | 问题 |
|---|---|---|
| 来源名 | 20px / w700 | 全卡最重，抢了标题的位置 |
| 条目标题（列表） | 14px / w600 | 比来源名轻 |
| 条目标题（网格） | 14px / w700 | 与来源名同重 |
| 序号 | 14px（列表）/ 12px（网格），**w900** | 比标题还重 |
| meta（2952 万热度） | 12px / w600 | 尚可 |
| 徽章（实时热搜） | 14px / w400，27 张卡里 19 张有 | 与来源名混排 |

按《Emphasize by de-emphasizing》的做法：想突出标题，就把其它层级**压下去**——来源名降到 12px/w500 灰、序号去掉底色改成 w500、meta 收成 12px/w400。

### P2-2 一屏只看得见 1/7，且没有明确入口

| 卡片 | 条目数 | 单行占位 | 可视高 | 一屏可见 | 隐藏 |
|---|---|---|---|---|---|
| 微博 | 30 | 55px | 415px | 7.5 行 | 23 条 |
| 酷安 | 20 | 66px | 415px | 6.3 行 | 14 条 |
| 华尔街见闻 | 10 | 55px | 415px | 7.5 行 | 3 条 |

卡片固定 500px，内部滚动**没有**文字级提示（上一轮加的底部渐隐只是弱信号）。《You don't have to fill the whole screen》指向的方向是：要么让卡片按内容长，要么显式告诉用户"下面还有 N 条"。

### P2-3 27 张卡同重量

每张都是 453×500、头部 20px/w700 来源名 + 22×22 三图标。整墙没有"哪张更值得看"的差别，正好踩在《Not all elements are equal》说的反面。

## 建议的改法（三档，按性价比排）

**A. 止血（3 个文件，约 30 分钟）** — P0-1、P0-2、P1-1、P1-2
- 序号：去掉基类 `text-white`，改成 `text-neutral-500` + `w500`，底色留 6%（对比度约 5.3:1）
- 原文按钮：`bgSolid` 改深一档或文字改 `text-neutral-100` 配实心底（二选一，视觉差别看截图定）
- ✦/⊕：`px-1` → `p-1.5`（点击区到 30×30 左右），并给足行内间距
- 三个头部图标补 `aria-label` + `title`

**B. 层级重构（约 1 小时）** — P2-1
- 来源名 20px/w700 → 14px/w600 + 副标题灰；标题成为全卡唯一 w700；序号降为 w500 无色块
- 行高与间距一起收（现在行占位 55-66px，收一档能多露 1-2 条）

**C. 结构（可选，需要你先定方向）** — P2-2、P2-3
- 卡片高度自适应（会牺牲整墙行对齐）
- 或"首条大卡 + 紧凑列表"（把 27 张等重卡变成有主次的墙）
- 或卡底加"还有 N 条 ⌄"的显式入口

- 每卡一条身份色条已经收敛，不动
